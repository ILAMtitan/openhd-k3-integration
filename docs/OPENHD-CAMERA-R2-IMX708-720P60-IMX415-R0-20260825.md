# OpenHD BeagleY-AI camera R2: qualified IMX708 720p60 + IMX415 R0

Date: 2026-08-26

This branch is the combined camera-development stack after the IMX708 path was
qualified end-to-end through OpenHD RF and the pre-hardware IMX415 work was
rebased on top of that frozen checkpoint.

## Camera types

- type 150: TI J722S IMX219 (preserved)
- type 151: TI J722S IMX708, final-qualified 1280x720p60 path
- type 152: TI J722S IMX415, pre-hardware R0 path

The clean-install BeagleY default remains IMX708/type 151. Installing the
IMX415 checkpoint explicitly changes the persisted primary camera to type 152
for that test unit only.

## Patch order

The order is deliberate:

1. existing qualified dirty/staged R3 consumer source at OpenHD commit `f07729b35e273fe3612e1aade030a7a86350d1ac`
2. patch 0009: native TI J722S IMX708/type151 additions, excluding its obsolete `gstreamerstream.cpp` hunk so the qualified 64-buffer R3 appsink is preserved
3. patch 0010: IMX708 1536x864p60 -> VISS -> 1280x720p60
4. patch 0011: final IMX708 qualification delta: VISS pools 2/2, explicit H.264 1280x720p60 Baseline Level 3.2, type151 dispatch
5. patch 0012: IMX415/type152 full-array -> VISS -> 1280x720p30

## Frozen IMX708 base

```
IMX708 1536x864 RAW10 @ ~60 (VBLANK=946)
  -> VPAC/VISS pool 2/2, 1536x864 NV12 @ 60
  -> TIOVX multiscaler
  -> 1280x720 NV12 @ 60
  -> Wave5 H.264 Baseline Level 3.2 @ 6 Mbit/s / GOP30
  -> OpenHD RTP / 64-buffer appsink
  -> WiFiBroadcast MCS2 / 20 MHz
```

This exact path passed the first OpenHD RF startup qualification and produced
clean received video on the ground laptop. The system uses the qualified
GStreamer V4L2 override under `/opt/ti-k3/gstreamer-overrides` so encoded
`sizeimage` is calculated from negotiated geometry instead of the Wave5
8192x8192 capability maximum; the historical 32 MiB CMA allocation failure is
therefore absent.

## IMX415 R0

```
IMX415 3864x2192 GBRG10 @ nominal 30
  -> VPAC/VISS 3864x2192 NV12 @ 30
  -> TIOVX multiscaler
  -> 1280x720 NV12 @ 30
  -> Wave5 H.264 @ 6 Mbit/s / GOP15
  -> OpenHD RTP
```

IMX415 remains pre-hardware-qualified. AE/AWB remain disabled and no default
manual exposure/gain values are invented. The final IMX708 GStreamer/CMA base
is inherited, but IMX415 RAW/VISS/Wave5/RF behavior still requires live
qualification before any R0 values are promoted.

## Qualification order

The IMX708 side is already frozen. For IMX415:

1. select/boot the correct B0569 overlay after confirming the live I2C address
2. qualify 3864x2192 RAW10 cadence and Bayer order
3. qualify VISS output and memory behavior
4. qualify multiscaler -> Wave5 1280x720p30 with the installed CMA override
5. inspect SPS/profile/level and software-decode the resulting H.264
6. install OpenHD type152 while keeping OpenHD disabled initially
7. manually start OpenHD and verify type152 pipeline, camera ownership, mapped override, CMA/kernel logs, and RF video

No EdgeAI memory-map, remoteproc firmware, or qualified RAW10LE compatibility
runtime changes are introduced by this refresh.
