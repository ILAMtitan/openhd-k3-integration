# OpenHD BeagleY-AI IMX415 R0 pre-hardware checkpoint

Date: 2026-08-24

This branch prepares an Arducam B0569 / Sony IMX415 OpenHD path on top of the
qualified IMX708 R1 checkpoint. **The IMX415 path is not yet hardware
qualified.** Existing IMX219 type 150 and IMX708 type 151 remain intact.

## Matching accelerator branch

Use `imx415-r0-20260824` in `ILAMtitan/ti-k3-accelerators` first. It contains:

- provisional CSI0 overlays for IMX415 address 0x37 and 0x1a
- 24-MHz / two-lane / 720-MHz-link fast-mode configuration
- full-array 3864x2192 SGBRG10 graph helper
- GBRG VISS preflight/smoke helpers
- untuned IMX415 DCC generator
- live-data checklist for R1

The already-qualified IMX708 RAW10LE TIOVX runtime is reused because it aliases
all Bayer RAW10LE orders, including `gbrg10le`.

## OpenHD type 152

Patch 0010 adds:

- `X_CAM_TYPE_TI_J722S_IMX415`
- ID 152
- name `TI_J722S_IMX415`
- user-visible mode `1280x720@30`

The BeagleY default remains IMX708/type 151 until IMX415 is physically
qualified. `apply-imx415-checkpoint.sh` explicitly switches an installed test
unit to type 152.

## R0 pipeline

```
v4l2src /run/ti-k3/camera-video, dmabuf-import
  -> gbrg10le 3864x2192 @ 30
  -> capssetter -> legacy gbrg10 metadata
  -> tiovxisp / VPAC VISS
       compatibility registry slot SENSOR_SONY_IMX219_RPI
       IMX415 DCC 3864x2192
       format-msb=9
       AE disabled
       AWB disabled
  -> NV12 3864x2192 @ 30
  -> tiovxmultiscaler
  -> NV12 1280x720 @ 30
  -> queue depth 1, leaky downstream
  -> Wave5 H.264
       6 Mbit/s
       GOP 15
  -> OpenHD h264parse / RTP MTU 1024 / appsink
```

Six Mbit/s is inherited as a known-clean RF operating point from IMX708 R1; it
is not yet an IMX415-specific RF qualification result.

## Image-quality boundary

R0 intentionally does not copy the IMX708 manual exposure values. IMX415 has a
different exposure timing model and an analogue-gain control range of 0..100.
`openhd-ti-imx415-prepare` only applies manual exposure/gain when explicitly
provided with:

- `OPENHD_IMX415_EXPOSURE`
- `OPENHD_IMX415_ANALOGUE_GAIN`

AE/AWB remain disabled until native IMX415 TI 2A sensor mapping exists.

## Reproducible apply path

`apply-imx415-checkpoint.sh` does not depend on the live modified OpenHD source
tree. It clones the pinned upstream OpenHD commit, applies patches 0001..0008,
verifies the known R3 tree hash, then applies IMX708 patch 0009 and IMX415 patch
0010 before building only OpenHD.

Once accelerator-side live qualification and DCC installation have passed:

```
sudo ./apply-imx415-checkpoint.sh
sudo systemctl start openhd.service
sudo ./verify-imx415-checkpoint.sh
```

The apply script leaves OpenHD stopped/disabled after installation so first
startup remains explicit.

## First live qualification order

Do not start with OpenHD. Use this order:

1. confirm kernel `CONFIG_VIDEO_IMX415` / `modinfo imx415`
2. identify the actual B0569 I2C address
3. select the matching accelerator overlay and cold boot
4. confirm probe/media graph/pixel rate
5. qualify 300-frame raw capture
6. generate/install IMX415 DCC
7. run `ti-k3-imx415-viss-smoke`
8. run local VISS -> multiscaler -> Wave5 H.264 test
9. install/build OpenHD type 152
10. start OpenHD and verify RF video

## Remaining unknowns before R1

- B0569 I2C strap on the actual unit
- whether the B0569 needs connector XCLR/reset or power-enable sequencing on
  BeagleY-AI
- whether mapping all three module supply handles to the connector 3.3-V parent
  is sufficient/reliable
- exact raw DMA stride/packing as exposed by TI CSI2RX at 3864x2192
- sustained raw/VISS throughput at the intended ~30 fps
- generated DCC correctness / black level / Bayer color response
- VISS full-frame resource usage
- TIOVX multiscaler behavior from 3864x2192 to 1280x720
- Wave5 local stability and latency at 720p30
- useful manual exposure/gain starting values
- physical RF quality at the inherited 6-Mbit/s baseline

Nothing in this branch changes the qualified EdgeAI memory map, firmware, or
IMX708 R1 runtime boundary.
